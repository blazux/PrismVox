# PrismVox 0.2.0

PrismVox is a self-hosted AI receptionist for SIP phone systems. It answers
calls, retrieves information, transfers callers, takes messages and runs outbound
missions, either on its own or connected to Prism.

## Changes since 0.1.1

- **Telephony configuration in Prism.** Manage the connection, models, SIP line,
  voices, MCP tools and resources from Prism's telephony settings. The Telephony
  app handles traffic, call history and outbound missions. The local PrismVox
  recovery console remains available at `/console`.
- **Models from Prism.** The switchboard and outbound agent can use a model
  source already configured in Prism, without copying its provider key into
  PrismVox. Recognized callers retain their personal Prism agent. Standalone
  installations keep their own configurable model endpoint.
- **More reliable calls and outcomes.** Caller ownership, transfer bridges and
  playback cleanup are handled consistently. Messages are confirmed as recorded
  after saving, and outbound results distinguish dialing, connection and outcome.
  Incomplete model streams do not release partially generated tool calls.
- **Safer outbound requests.** The queue supports pagination. Unconfirmed
  scheduling retains the draft and can check the same request again. API clients
  can supply `request_id` to avoid creating duplicate missions when retrying.
  Uncertain dial outcomes are checked against Asterisk before further action;
  unresolved cases require operator review.
- **Security updates.** Browser writes authenticated with HTTP Basic reject
  cross-origin requests. Private model, embedding, speech, Prism and ARI API
  requests reject redirects to another origin. ARI WebSocket authentication
  uses a header rather than URL credentials. Runtime and library dependencies
  have been updated.
- **Supported telephony runtime.** The Asterisk image now uses Asterisk 20.22.0
  LTS on Ubuntu 24.04. Published agent, console and Asterisk images include
  native AMD64 and ARM64 builds; isolated telephony tests run on both architectures.

## Before upgrading

Wait for active calls and outbound work to finish before restarting services.
Do not retry a mission with an uncertain outcome until you have checked its call
history.

Back up PostgreSQL and all six persistent volumes: `pgdata`, `secrets`,
`asterisk_dynamic`, `sounds`, `tts_cache` and `ui_certs`. Keep your `.env`, Compose
overrides and any custom Asterisk configuration. Take a logical PostgreSQL backup
or stop the database before copying its data directory. Preserve the encryption
key in `secrets`: a database backup alone cannot restore encrypted credentials.
Keep the same Compose project name so the existing volumes are reused. Do not
run `docker compose down -v`.

The console applies additive database migrations for saved connections and
outbound request tracking at startup. Keep a pre-upgrade backup for rollback.

The language model is not bundled or replaced by this release. Preserve your
model, speech and embedding endpoints and confirm that their services are
running. Update connected Prism installations to Prism 1.1.0 for the model relay.
Saved Prism connection settings take precedence over environment bootstrap
values; changing the saved Prism server URL requires a new token.
Configure the final API URL when a provider redirects requests to a different
scheme, host or port.

For custom Asterisk deployments, review compatibility with Asterisk 20 before
updating. The obsolete Asterisk 18 modules `app_ices`, `app_image`, `app_nbscat`,
`app_url` and `chan_oss` are not included. PrismVox's supplied dialplan does not
use them. Preserve your custom configurations and verify their applications.

New SIP TLS configurations verify the server certificate. Existing trunks retain
their previous verification choice; upgrading does not secure a trunk that has
verification disabled. Obtain the official CA chain and matching SBC hostname
from your carrier before enabling `SIP_TLS_VERIFY_SERVER=yes`. Mount a private CA
bundle and set `SIP_TLS_CA_FILE` when needed. Do not trust a captured certificate
without verifying its origin. UDP does not encrypt SIP or media.

## Update

Retrieve the current Compose files, retain your existing `.env` and overrides,
and set `PRISMVOX_TAG=v0.2.0` in that `.env` for all three PrismVox images. Then run:

```sh
docker compose pull
docker compose up -d --no-build
```

Use `PRISMVOX_TAG=latest` instead to follow stable releases. Leaving the tag unset
follows `unstable`, the main-branch builds.

The default PostgreSQL major remains 16. An existing `./ui/app:/app` development
mount overrides the published console code; remove that mount when switching to
the release images. If you still use the removed local speech overlays, select
direct ElevenLabs or your separately deployed STT/TTS APIs before updating. Keep
the old speech services and their volumes until their replacement is verified.

Check console login, the Prism connection if used, SIP registration, call history
and speech/model connectivity. Complete a controlled inbound and outbound call
before returning the line to regular use. For rollback, retain the previous
image versions and a matching pre-upgrade database, key and configuration backup;
reverting images alone does not reverse database migrations.
